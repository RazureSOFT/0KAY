# Yandere affect dynamics — 移植说明与出处

`src/life/cognition/yandere.py` 是对外部研究项目 **`yandere_engine`** 的移植。
本文记录**移植了什么、故意没有移植什么、以及它和 LIFE 已有的三个相邻模型是什么关系**。

## 1. 出处

核心论文（移植的正是这一篇）：

> 柳朋輝・米澤朋子（2023）「仮想エージェントにおけるヤンデレの実装」
> HAI シンポジウム 2023, P-60

论文把ヤンデレ定义为 **「過度な好意による感情の急変と過剰な愛情表現」**
（因过度好意导致感情急变、并伴随过度爱情表现的性格），引擎把它拆成三条可计算主张：

| 主张 | 公式 | 位置 |
|---|---|---|
| **C1 急変**：情绪反应利得是好意 A 的超线性函数 | `g⁺=k·(1+k_excess·A²)`；`g⁻=k·(1+k_excess·A²·(0.6+1.4·J))` | `YandereDynamics.perceive` |
| **C2 過剰**：表达强度对好意超线性 | `I = max(v,0)·(1+excess·A²)`；`darkness = max(-v,0)·(1+excess·A²)` | 同上 |
| **C3 円環**：感情円環 (v,a) + 迟滞模式机 NORMAL/DERE/YAMI | 入口/出口阈值分离 + 嫉妬镇静条件 | `_update_mode` / `_enter_yami` |

内部状态：`v`(valence) `a`(arousal) 在 Russell (1980) 情感圆环上；每人 `A`(好意) `T`(信頼)；全局 `J`(嫉妬)。
输入层是 12 种事件（`EVENT_EFFECTS`），对应论文的「ユーザの識別・状態認識」。

`traits.py` 里的 OCEAN → 动力学参数映射（`traits_to_profile`）来自另外两篇论文的合成推演：
心理尺度签名（低宜人性·高神经质）→ OCEAN→引擎写像 → 情感圆环动力学。
`tests/test_yandere.py::TestTraitsBridge::test_signature_traits_reach_yami` 就是这条链的可执行复现。

## 2. 移植了什么

- 情感圆环坐标系与 Russell 八象限标签（`emotion_label`）
- 12 种事件词汇与其原始心理冲击（`EVENT_EFFECTS`）
- 四条原型（病娇 / 傲娇 / 中性 / 傲娇→病娇）与它们的参数集（`DereProfile` / `TYPES`）
- C1 / C2 / C3 三条动力学（含病み期的反芻振荡）
- OCEAN → 参数写像与病娇心理尺度签名
- `YandereSystem` 外覆层：真实互动信号 → 事件；`tick` / `context` / `guard` / 持久化

## 3. 故意没有移植什么

研究引擎的 **「全栈模式」（30 篇论文串联）没有被移植**，原因是那部分里 12 篇是综述/深度模型/数据集，
引擎自己用「透明确定性替身」承担它们在管线中的**功能角色**（PAPER_MAP 的用词是「角色实现」，
并明确声明不声称复现论文性能）。LIFE 已经有自己的感知、人格、反应与对话层，
把 12 个占位模块一起搬进来只会制造第二套平行的、Duplicated 的管线。

具体未移植：`perception`（多模态融合替身）、`personality`（特质回归替身）、
`reactions`（7 属性反应编码 + softmax 采样）、`dialogue`（MEGE/REG/ES4R）、
`display`（抑制与演技）、`stack`（全管线编排）、`render`（颜文字/台词渲染）。

其中 `render`（颜文字与固定台词）是**刻意丢弃**的：LIFE 的台词由模型生成，
硬编码台词会与人格层冲突。动力学层只输出 `mode` / `intensity` / `darkness` 供提示词使用。

## 4. 与 LIFE 已有三个相邻模型的关系

这是最容易误解的一点。LIFE 的认知层里**已经有三处**与「病娇」有关的模型，本电路与它们**刻意保持分离**：

| 模块 | 是什么 | 与本电路的区别 |
|---|---|---|
| `cognition/attachment.py` | 病态依恋的**静态分类**（依存型 / 妄想型 / 监视型 …） | 分类学，不是动力学 |
| `cognition/tsundere.py` | A/T/Y **三变量 ODE**，黑化由 `k_y·A·r`（已动心的心被拒绝）驱动 | 连续时间 ODE，无圆环、无嫉妒变量、无迟滞模式机 |
| `cognition/persona_dynamics.py` | Q-learning 动作选择层，**也**有一个 `yandere` 模式 | 强化学习层，求解「选什么动作」 |

`yandere.py` 是**论文的形式化**：事件词汇 + 超线性增益 + 圆环迟滞模式机 + 嫉妒。
三者可同时开启，互不冲突，但**是否长期保留四个重叠的「病娇相关」模型是需要维护者决定的架构问题**——
本移植保持 opt-in（默认关闭）且不改动任何既有行为，就是为了让这个决定可以独立做。

## 5. 诚实声明

1. 各增益、阈值、事件数值是**为使论文主张的方向可复现而设定的假设值**，
   **不是从论文拟合数据**（该论文仅 4 页，未报告拟合系数）。机制方向忠实于论文。
2. 「傲娇→病娇」（`hybrid`）是研究引擎的**探索性扩展，没有对应的已发表论文**。
   只作假设推演，不得引用为文献结论。
3. 嫉妬 `J` 是全局变量（未按对象分槽），这是研究引擎的已知局限，一并保留。
4. 这是**虚构角色行为模型，不是诊断工具**，绝不可用于评判真实的人。

## 6. 用法

- 设置项：`cog_yandere_enabled`（0/1）、`cog_yandere_type`（病娇 / 傲娇 / 中性 / 傲娇→病娇）
- 或直接在人设里写关键词自动开启并填充初始值：「病娇 / 占有欲 / 执念 / 黑化」→ 病娇；「傲娇 / 嘴硬」→ 傲娇→病娇
- 状态读出口：`cognition_status()["yandere"]`（模式、圆环象限、好意、嫉妒、表达/阴暗、安全层）
- 阴暗度 ≥ 0.70 自动进入安全层（`guard()` 为私有指令，不可说出或转述）
